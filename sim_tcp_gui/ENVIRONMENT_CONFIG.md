# 环境配置 → DDS → 车端 0x07

编辑模拟器目录中的 [environment_config.json](environment_config.json)，即可配置前后障碍物和周边车辆。当前场景不显示行人：前后各两辆宽体车障碍物，中心坐标分别为 `[-6,8,0]`、`[6,8,0]`、`[-6,-8,0]`、`[6,-8,0]`，均距本车后轴中心 10 m，宽 2.5 m、高 2 m。

四辆 V2V 按前、后、左、右顺序配置，分别位于 `[0,20]`、`[0,-20]`、`[-20,0]`、`[20,0]` 米，绝对航向分别为 30°、100°、200°、320°。位置随车保持相对距离，绝对航向不随本车转向改变。

## 加载与生效

`bridge_config.json` 中的 `dds_output.environment_config_file` 指定配置文件，相对路径基于模拟器源码目录解析，不受进程工作目录或 `SIM_BRIDGE_CONFIG` 位置影响。默认值为 `environment_config.json`。Linux 首次启用需要重启模拟器；后续每 500 ms 检查文件变化，无需重启。

文件必须包含 `front_obstacles`、`back_obstacles`、`round_vehicles` 三个数组。文件模式完整接管三组列表，不与内联配置混合；删除该设置或设为空字符串时，继续使用原内联列表，内联周边车辆仍使用原经纬度格式。

整份文件读取、数值及容量校验成功后才替换有效缓存。编辑过程中出现 JSON 错误、缺失字段、文件丢失、越界或超量时保留上一份有效数据，并记录错误。启动时指定的文件无效则明确报错，不能以空场景代替。清空列表请保留三项键并明确写入空数组；空数组仍发布 DDS，以清除车端旧列表。推荐用临时文件写完后替换原文件，避免编辑器分步保存出临时有效但不完整的场景。

`GET /api/state` 的 `environment_config` 返回 `source`、`loaded`、实际 `path`、已加载的 `mtime_ns`、`front_count`、`back_count`、`vehicle_count`、`packet_bytes`、`last_error`。错误状态独立于 DDS 发布计数，不会被下一次发布成功覆盖。

## 坐标与字段

坐标原点为本车后轴中心，横向正右、纵向正前，距离及尺寸均为米；航向以正北为 0°、顺时针增加。前后分组不会改变坐标正负号，也不会自动对距离取绝对值。该配置描述随车保持相对位置的场景，地图上的固定物体编辑不参与此文件的数据生成。

| 列表 | 字段 | 含义和范围 |
| --- | --- | --- |
| 前/后障碍物 | `type` | 整数 0 包围盒、1 散点 |
| 包围盒 | `box.center` | `[横向,纵向,高度]`；横纵向范围 -327.68～327.67 m，高度必须为有限 float |
| 包围盒 | `box.object_type` | 整数 0～252，省略为 0；DDS 原始分类，不是 TCP 类型 |
| 包围盒 | `box.object_width` / `object_height` | 必填，0～655.35 m；分别对应宽度和高度，不是长度 |
| 散点 | `scatter.center` | 与包围盒中心格式相同；TCP 不传散点尺寸 |
| 周边车辆 | `device_type` | 整数 0～255；既有约定 0 矿车、1 挖机、2 RSU、3 装载机、4 洒水车、5 指挥车、6 平地机 |
| 周边车辆 | `lateral_m` / `longitudinal_m` | 必填，横向/纵向相对距离，必须为有限数值；转换结果必须在合法经纬度范围 |
| 周边车辆 | `heading_deg` | 绝对航向，单位度，归一化至 [0,360)，不叠加本车航向 |
| 周边车辆 | `heading_offset_deg` | 兼容旧配置：相对本车的航向偏差，单位度，支持负值并归一化；与 `heading_deg` 必须二选一 |

不接受 NaN、Infinity、布尔值冒充数字、数字字符串或未支持字段。当前车辆障碍物使用 `object_type=1`（宽体车），没有自行新增行人或“石头”等协议分类。障碍物高度坐标保留在 DDS 中，`0x07` 不传该坐标。

## 周边车辆坐标转换

每次发布使用同一份本车/地图快照。设本车航向为 H，车辆相对横纵向距离为 x、y：

```text
东向偏移 = x*cos(H) + y*sin(H)
北向偏移 = -x*sin(H) + y*cos(H)
使用 heading_deg 时：周边车辆航向 = heading_deg mod 360
使用 heading_offset_deg 时：周边车辆航向 = (本车航向 + heading_offset_deg) mod 360
```

偏移叠加到本车地图 `x_m/y_m`，使用与动力学相同的地图原点和比例换算成经纬度：每纬度 111320 m，经度比例为 `max(111320*cos(地图中心纬度), 1)`。因此修改本车 GPS、航向或地图原点后，周边车辆会跟随重新计算；模拟器不直接组装或发送 `0x07`。

## DDS 与 TCP 对应

| 配置数据 | DDS Topic | DDS 类型 | 车端用途 |
| --- | --- | --- | --- |
| `front_obstacles` | `fusion_front_scatter_box_` | `DDS_SensorFuseResults` | 障碍物列表前半部分 |
| `back_obstacles` | `fusion_back_scatter_box_` | `DDS_SensorFuseResults` | 障碍物列表后半部分 |
| `round_vehicles` | `CloudRoundVehicleList` | `CloudRoundVehicleList` | 周边车辆列表 |
| 本车动力学定位 | `GpsImuInfo`（既有配置名称） | `GpsImuInfo` | 本车经纬度、航向 |

沿用现有 DDS 发布间隔和车端 `0x07` 调度，不修改 IDL、QoS、TCP 协议或发送周期。单份模拟器快照的三组列表一起更新，但不同 DDS Topic 的车端回调仍独立执行，不提供跨 Topic 事务。

`0x07` 数据区依次为：时间 8 字节、本车经度 4、纬度 4、航向 2、障碍物数量 2、障碍物条目、周边车辆数量 2、周边车辆条目。前向在前、后向在后，保留各自配置顺序，不额外传方向标志。

- 每个障碍物 9 字节：类型 1、宽度 2、高度 2、纵向距离 2、横向距离 2。包围盒 TCP 类型为 `object_type+3`，散点类型固定为 1、宽高为 0。
- 尺寸和距离乘 100，沿用车端截断规则；负距离按有符号厘米的二进制位模式传输，接收端按 `int16` 解码。
- 每辆周边车辆 11 字节：类型 1、经度 4、纬度 4、航向 2。经度为 `(经度+180)×10⁷`，纬度为 `(纬度+90)×10⁷`，航向为 `航向×10`。
- 多字节字段均为大端，整包保留原头部和 XOR。每路障碍物最多 200 条、周边车辆最多 50 条，并且整包必须满足 `47+9×障碍物总数+11×车辆数≤1024`，超限整份拒绝，不截断、不分包。
